# Матрица экспериментов M2

**Статус:** проект матрицы для утверждения; запусков не было.
**Дата среза:** 24 ноября 2026 года.

## Основные конфигурации

Каждый quant-вариант строится от одного и того же закреплённого checkpoint соответствующей модели, через один промежуточный F16 GGUF и одним `llama.cpp` quantizer. KV-cache во всей основной серии — F16; изменение типа cache не допускается. `imatrix` выключена.

| Модель | F16 | Q8_0 | Q6_K | Q5_K_M | Q4_K_M | Статус |
| --- | --- | --- | --- | --- | --- | --- |
| Qwen3-1.7B | да | да | да | да | да | Обязательные — если общий preflight и безопасная загрузка успешны. |
| Qwen3-4B | да | да | да | да | да | Обязательные. Центральная линия для H1 и взаимодействия quantization × context. |
| Qwen3-8B | нет | условно | да | условно | да | Q6_K/Q4_K_M обязательны после безопасного короткоконтекстного smoke; Q8_0/Q5_K_M включаются, если пилот проходит safety limits. F16 исключён до пилота: веса около 16,4 GB по 8,19B × 2 bytes без runtime/cache и несовместимы с заданным бюджетом. |

Итого — 12 обязательных model-quantization строк и до 2 условных строк для 8B. Если одна обязательная строка не проходит загрузку/ресурсный порог, её не заменяют менее точной схемой без обновления протокола. Для чистых внутримодельных контрастов в основной статистике нужны F16 и соответствующий quant-вариант одного ID.

## Валидационная когорта

Для `Qwen/Qwen3.5-4B` предлагаются F16, Q6_K, Q4_K_M; Q8_0 условен по пилоту. F16 и context F16/Q6/Q4 включаются только если каждая строка отдельно проходит safety limits; если F16 не проходит, validation можно ограничить Q4_K_M, но вывод о non-inferiority к F16 недоступен. Это отдельная когорта: мультимодальность и гибридные состояния отличаются от основной Qwen3 серии. Все тесты подаются только как текст. До использования проверяется точная конфигурация `Qwen3_5ForConditionalGeneration`, шаблон диалога, GGUF conversion и Metal backend на выбранном commit.

## Дополнительные варианты, исключённые из первичной матрицы

| Вариант | Причина |
| --- | --- |
| Q3_K_M, IQ4_XS и другие IQ/K-схемы | Резко расширяют число сравнений; эффективный BPW/состав типов меняется. Допустимы только как заранее выделенная exploratory строка после основной серии. |
| GPTQ, AWQ, SmoothQuant и другие форматы | Это иные алгоритмы, calibration и kernel/runtime пути. Они не являются прямым контролем GGUF при одном `llama.cpp` серверном тракте; отдельное исследование потребует собственного дизайна. |
| KV-cache Q8/Q4 и KIVI/KVQuant | Меняют второй независимый источник качества/памяти. Основная серия фиксирует F16 KV-cache; cache quantization — отдельное последующее исследование. |
| Активированные calibration/imatrix варианты | Меняется процедура подготовки квантованных весов; без отдельного калибровочного дизайна не включать. |
| Base, Thinking-only и мультимодальные prompts | Тип постобучения/задач отличался бы от основной текстовой instruct-линии. |

## Данные и число запросов на одну основную конфигурацию

| Набор | Роль | Планируемая выборка | Метрика |
| --- | --- | ---: | --- |
| MERA MathLogicQA `train` (680) | Выбор конфигурации | 100 | Accuracy |
| MERA ruOpenBookQA `train` (2338) | Выбор конфигурации | 100 | Accuracy; macro-F1 вторично |
| MERA MathLogicQA `test` (1143) | Отложенная проверка на виденной при выборе задаче | 200 | Accuracy |
| MERA MultiQ `test` (900) | Отложенная проверка типа задачи | 200 | Token-F1; EM вторично |
| MERA PARus `dev` (100) | Отложенная проверка типа задачи | Все 100 | Accuracy; опубликованный `test` закрытый и локально не оценивается |
| MERA ruOpenBookQA `test` (400) | Отложенная проверка на виденной при выборе задаче | 200 | Accuracy; macro-F1 вторично |
| LIBRA Mini: `ru_babilong_qa3`, `long_context_multiq`, `matreshka_names`; 4K/8K/16K | Длинный контекст; только выбранные строки | 30 на каждую ячейку task × length = 270 на configuration | Официальный EM |

Основная качество/выбор выборка: 200 development + 700 held-out запросов на конфигурацию. Одна генерация на пример; нет повтора качества разными seed. Табличный основной сценарий и объём запросов предполагают, что Qwen3.5 F16/Q4 validation rows проходят пилот; при safety-исключении их число пересчитывается до открытия held-out результатов.

LIBRA Mini context interaction рассчитывается для Qwen3-4B F16/Q6_K/Q4_K_M. Qwen3.5-4B Q4_K_M проходит отдельную контекстную проверку; если пилот позволяет, дополнительно F16/Q6_K. Для каждой длины выбирается одинаковый набор записей между сравниваемыми конфигурациями. Ожидаемые доступные количества по трём задачам превышают 30 в каждой ячейке: `ru_babilong_qa3` 60/68/69, `long_context_multiq` 158/121/83, `matreshka_names` 150/150/145 для 4K/8K/16K соответственно. См. [источник LIBRA](https://huggingface.co/datasets/ai-forever/LIBRA) и текущую [карточку MERA](https://huggingface.co/datasets/MERA-evaluation/MERA).

## План perf-измерений

Контролируемая perf-подсерия: Qwen3-4B F16, Q4_K_M, Q6_K; фиксированные workload длиной 512, 4096, 8192 и 16384 input tokens; один последовательный запрос; до 128 generated tokens; 30 повторов одной длины после 3 warm-up на ячейку. Это 360 измеренных + 36 прогревочных запросов. Отдельно сохраняются метрики на естественных prompts основной серии для всех конфигураций; они являются workload-наблюдениями и не заменяют стандартизованный perf срез.

Если workload не может быть воспроизведён с требуемой длиной без добавления значимого содержательного сигнала, input-пакет фиксируется как отдельный нейтральный текстовый fixture. Точный текст, token count и hash должны быть опубликованы. Perf-запрос не включается в dataset quality.

## Статус допуска

Ни одна строка не считается выполненной или гарантированно совместимой. Включение условной строки возможно только по критериям [пилота](pilot-plan.md) и безопасности из [протокола измерения](measurement-protocol.md). Если доступный ресурс не позволяет полный план, M2 owner должен утвердить сокращённый вариант **до** первого тестового прогона; недопустимо выбирать выгодный subset после просмотра результатов.
